# 读小说核心功能与数据结构梳理

本文档梳理本系统**自主设计的核心功能：读小说**，包括功能入口、数据流、以及**小说、小说角色、章节、解析结果、TTS 结果**等核心数据结构与存储关系。

---

## 一、功能概览与入口

### 1.1 功能目标

- **读小说**：用户创建/导入小说 → 为小说维护角色与章节 → 对章节进行 **LLM 解析**（分出旁白与对话、说话人、情感等）→ 为解析后的**段落**绑定语音并 **TTS 合成** → 试听/导出整章音频。
- 解析、语音绑定、合成依赖外部 LLM/TTS 配置，但**小说、角色、章节、解析结果、TTS 结果**均为本系统内持久化与展示的核心数据。

### 1.2 页面与路由

| 页面 | 路由 | 作用 |
|------|------|------|
| 读小说列表/详情 | `/read-novels` | `ReadNovels.vue`：小说列表、当前小说基本信息、角色列表、章节列表；新建/编辑小说、角色、章节；选择章节后跳转至章节详情 |
| 章节详情（解析+TTS） | `/chapters/:chapterId` | `ReadNovelsChapter.vue`：单章正文编辑、LLM 解析、解析结果（段落列表）展示与编辑、段落 TTS 配置、单段/整章 TTS 合成、TTS 结果试听与返回 |

从章节列表点击某章会 `router.push(\`/chapters/${chapterId}\`)`，进入 `ReadNovelsChapter` 进行解析与 TTS 操作。

### 1.3 数据流概览

```
[小说列表] → 选小说 → 加载该小说的 [角色] + [章节列表]
                → 选章节 → 进入 /chapters/:chapterId
                    → 加载 [章节详情] + [该小说角色] + [解析结果 parsedData] + [TTS 结果 ttsResults]
                    → 解析 → 写入章节的 parsedData（segments）
                    → 段落绑定角色/语音 → 合成 → 写入章节的 ttsResults / 段落 audioUrl 等
```

---

## 二、核心数据结构

### 2.1 小说（Novel）

**存储**：`server/models/Novel.js`，键 `novels`（storage 单文件/键），数组，每项为一本小说。

**服务端创建时的结构**（`Novel.createNovel`）：

```js
{
  id: string,                    // uuid
  title: string,
  description: string,
  author: string,
  cover: string | null,
  characters: Array<Character>,  // 内嵌角色列表，见下
  createdAt: string,              // ISO
  updatedAt: string,
  chapterCount: number,
  wordCount: number,
  settings: {
    defaultLLMProvider: string,
    defaultTTSProvider: string,
    defaultVoiceSettings: { speed, pitch, volume, emotion, style }
  }
}
```

**前端类型**：`ui/src/types/ReadNovels.ts` 的 `Novel`（无 `chapterCount`/`wordCount` 时由后端补全，前端可忽略或只读）。

- 角色**内嵌**在小说对象中：`novel.characters`，不单独表存储。
- 小说维度 API：`novel:get-all`、`novel:get`、`novel:create`、`novel:update`、`novel:delete`。

---

### 2.2 小说角色（Character）

**存储**：同上，存在于 `Novel.characters` 数组中，无单独存储键。

**服务端添加时的单条结构**（`Novel.addCharacter`）：

```js
{
  id: string,           // uuid
  name: string,
  type: "main" | "secondary" | "minor",
  gender: "male" | "female" | "unknown",
  age: "child" | "youth" | "middle" | "elder" | "unknown",
  description: string,
  voiceModel: string,
  aliases: string[],
  ttsConfig: {
    provider: string,   // TTS 服务商类型，如 "azure"
    model: string,      // 语音模型 code
    speed, pitch, volume, emotion, style
  },
  createdAt: string
}
```

**前端类型**：`ReadNovels.ts` 的 `Character`（含 `updatedAt?`）。

- 角色**按小说维度**读写：`character:get-by-novel`、`character:create`、`character:update`、`character:delete`。
- 创建/更新角色时请求体带 `novelId`；后端在 `Novel.getCharacters(novelId)` 或增删改时从对应小说的 `characters` 数组操作。

---

### 2.3 章节（Chapter）

**存储**：`server/models/NovelChapter.js`，键 `novel-chapters`，数组，每项为一章。

**服务端创建时的结构**（`createNovelChapter`）：

```js
{
  id: string,
  novelId: string,
  title: string,
  content: string,           // 正文原文
  order: number,
  processed: boolean,        // 是否已解析
  llmProvider: string,       // 使用的 LLM 服务商 id
  createdAt: string,
  updatedAt: string,
  parsedData: null | ParsedChapter,   // 解析结果，见下
  ttsResults: {
    segments: [],
    audioFiles: [],
    mergedAudioFile: null,
    status: "pending" | "processing" | "completed" | "failed",
    createdAt: null,
    completedAt: null
  }
}
```

**前端类型**：`ReadNovels.ts` 的 `Chapter`（`parsedData?: ParsedChapter`，`ttsResults?: ChapterTTSResults`）。

- **解析结果**与 **TTS 结果**均**内嵌**在章节对象中：`chapter.parsedData`、`chapter.ttsResults`。
- 章节维度 API：`chapter:get-by-novel`、`chapter:get`、`chapter:create`、`chapter:update`、`chapter:delete`。
- 解析结果单独接口（仍读写同一章节的 `parsedData`）：`parsed-chapter:get-by-chapter`、`parsed-chapter:update`（实为 `updateParsedChapter(chapterId, parsedChapterData)` → `NovelChapter.updateChapterParsedData`）。

---

### 2.4 解析结果（ParsedChapter / parsedData）

**存储**：章节内嵌字段 `chapter.parsedData`，由 `ChapterProcessingController`（`llm:parse-chapter`）在解析成功后写入。

**结构**（与前端 `ParsedChapter` 一致）：

```ts
{
  title: string,                    // 通常与 chapter.title 一致
  segments: Array<ParsedSegment>,   // 见下
  processedAt?: string,
  provider?: string,
  llmProvider: string,
  createdAt: string,
  updatedAt: string
}
```

**ParsedSegment**（单段解析结果，前端 `ParsedSegment` 扩展自 `ScriptSegment`）：

```ts
{
  index: number,
  text: string,              // 该段文本
  character: string,         // "旁白" 或角色名
  emotion?: string,
  tone?: string,
  speed?: number,
  mimicry?: string,
  voice?: string,
  ttsConfig?: {
    provider?: string,
    model?: string,
    speed?: number,
    pitch?: number,
    volume?: number,
    emotion?: string,
    style?: string
  },
  synthesisStatus?: "unsynthesized" | "synthesized",
  audioUrl?: string,
  audioPath?: string
}
```

- 解析时由 LLM 返回「谁说的 + 文本 + 情感等」，后端规范为 `character`（"旁白" 或角色名）、`text`、`ttsConfig` 初值等，再写入 `parsedData.segments`。
- 前端在章节详情页根据 `character` 匹配 `novel.characters`，把角色的 `ttsConfig` 应用到段落的 `ttsConfig`，再用于 TTS 合成。

---

### 2.5 TTS 结果（ttsResults / ChapterTTSResults）

**存储**：章节内嵌字段 `chapter.ttsResults`。

**结构**（与前端 `ChapterTTSResults` 一致）：

```ts
{
  segments: Array<{
    index: number,
    audioPath?: string,
    audioUrl?: string,
    duration?: number,
    synthesisStatus: "pending" | "processing" | "completed" | "failed"
  }>,
  audioFiles: string[],
  mergedAudioFile?: string | null,
  status: "pending" | "processing" | "completed" | "failed",
  createdAt?: string,
  completedAt?: string,
  updatedAt?: string
}
```

- 单段合成后，段落级音频会写在 `parsedData.segments[i].audioUrl` / `audioPath`，且可能同步更新到 `ttsResults.segments`；整章合并结果在 `ttsResults.mergedAudioFile`。
- 前端 `ReadNovelsChapter.vue` 中 `ttsResults` 有时为「TtsResult 数组」形态（如合并后只保留一条 merged 记录），与后端返回的 `chapter.ttsResults` 对象可做一层兼容转换。

---

## 三、数据关系与存储汇总

| 实体 | 存储位置 | 关系 |
|------|----------|------|
| 小说 | `novels` 数组，每项一本 | 含 `characters[]` |
| 角色 | 内嵌在 `Novel.characters` | 属于一本小说，无单独表 |
| 章节 | `novel-chapters` 数组，每项一章 | `novelId` 指向小说；含 `parsedData`、`ttsResults` |
| 解析结果 | 内嵌在 `Chapter.parsedData` | 属于一章；含 `segments[]` |
| TTS 结果 | 内嵌在 `Chapter.ttsResults` | 属于一章 |

- **小说 ↔ 角色**：一对多，角色仅存于小说内。
- **小说 ↔ 章节**：一对多，章节表存 `novelId`。
- **章节 ↔ 解析结果**：一对一，解析结果内嵌在章节。
- **章节 ↔ TTS 结果**：一对一，TTS 结果内嵌在章节。
- **解析段落 ↔ 角色**：通过 `segment.character` 与 `characters[].name`（及 `aliases`）匹配，用于确定该段用哪个角色的 `ttsConfig`。

---

## 四、主要业务流程与涉及数据

### 4.1 解析章节（LLM）

1. 入口：`ReadNovelsChapter.vue` 中「解析」→ 调用 `llm:parse-chapter`（ChapterProcessingController）。
2. 后端：取章节 `content`、`llmProvider`，调 LLM 得到原始段落列表 → 规范为 `ParsedSegment[]`（含默认 `ttsConfig`）→ 组装为 `parsedData` → `NovelService.updateParsedChapter(chapterId, parsedData)` → 写入 `chapter.parsedData` 并置 `chapter.processed = true`。
3. 涉及数据：`Chapter.content`、`Chapter.llmProvider`、`Chapter.parsedData`（含 `segments`）。

### 4.2 段落绑定角色与 TTS 合成

1. 前端：章节详情页根据 `segment.character` 匹配 `characters`，用角色 `ttsConfig` 填充/更新 `segment.ttsConfig`（`ensureAllSegmentsTtsFromCharacters` 等）。
2. 单段合成：调用 `tts:synthesize-segment`，传入 `chapterId` 与 `segmentData`（含 `ttsConfig`）；后端用 `segment.ttsConfig.provider`、`segment.ttsConfig.model` 等合成，写回段落 `audioUrl`/`audioPath` 或汇总到 `ttsResults`。
3. 全章合成：调用 `tts:synthesize-all-segments`，后端用角色列表与 `parsedData.segments` 做角色映射，逐段合成后合并，更新 `chapter.parsedData` 与 `chapter.ttsResults`。
4. 涉及数据：`Chapter.parsedData.segments[].ttsConfig`、`Novel.characters[].ttsConfig`、`Chapter.ttsResults`。

### 4.3 更新解析结果（如改 LLM 服务商、改段落）

1. 前端：切换 LLM 服务商后保存章节（`llmProvider`）、或编辑段落后保存解析数据。
2. API：`parsed-chapter:update` 或 `chapter:update`（带 `parsedData`）→ `NovelService.updateParsedChapter` / `NovelChapter.updateNovelChapter`。
3. 涉及数据：`Chapter.llmProvider`、`Chapter.parsedData`。

## 六、IPC / 接口速查（读小说相关）

- **小说**：`novel:get-all`、`novel:get`、`novel:create`、`novel:update`、`novel:delete`
- **角色**：`character:get-by-novel`、`character:create`、`character:update`、`character:delete`
- **章节**：`chapter:get-by-novel`、`chapter:get`、`chapter:create`、`chapter:update`、`chapter:delete`
- **解析**：`parsed-chapter:get-by-chapter`、`parsed-chapter:update`；业务解析 `llm:parse-chapter`、`llm:parse-chapters-batch`
- **TTS 结果**：`tts:get-results`（按章节取）；合成 `tts:synthesize-segment`、`tts:synthesize-all-segments`、`tts:synthesize-full-chapter`（见 SegmentTTSController）

以上即读小说功能的核心数据结构与流程梳理。
