# 一个完全基于 AI 的有声书 Agent 设计思考

## 需求目标

- **产品形态**：用户提供小说来源（见下方输入方式）后，由 AI Agent 自动完成「获取/解析原文 → 分章 → 角色识别与 TTS 绑定 → 按角色生成对话脚本 → 合成语音 → 合并为整章音频」的全流程，产出可直接收听的有声书。
- **核心价值**：最小化人工介入，从「书名或本地内容」到「可播放音频」一站式自动化。

---

## 输入与输出

| 项目 | 说明 |
|------|------|
| **输出** | 按章节组织的完整有声书音频（每章一条合并后的音频） |

### 输入方式（二选一或并存）

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| **按书名/作者获取** | 用户输入小说名称、作者等可定位信息，由 AI 自动爬取或检索并获取全文 | 公开可获取的网络小说、已知书名且能拿到正文的情况 |
| **用户提供文件/内容** | 用户直接上传小说文件（如 txt、epub 等）或粘贴/导入正文内容 | AI 拿不到内容时：版权限制、非公开、自写稿、本地保存的文本等 |

- 产品需同时支持两种入口，并在「内容获取与结构化」阶段统一为「已有全文」后再进入分章及后续流程。

---

## 工作流程

### 1. 内容获取与结构化

1. **用户输入**（两种入口任选）：
   - **入口 A**：小说名称、作者等信息 → 由 AI 根据信息获取全文并持久化保存；
   - **入口 B**：用户上传小说文件（txt/epub 等）或粘贴/导入正文内容 → 解析并持久化保存（适用于 AI 拿不到内容的情况，如版权、非公开、自写稿、本地文本等）。
2. **全文就绪**：无论哪种入口，此处得到「已有全文」的同一状态。
3. **分章节**：AI 将全文切分为章节，建立章节级结构。

### 2. 角色体系构建

4. **角色抽取**：AI 分析全文，识别主角、配角等重要角色，并结构化存储（可随后续步骤增量补充）。
5. **TTS 角色绑定**：根据角色性别、性格等属性，为每个小说角色分配合适的 TTS 音色；同时预留若干「龙套」男女 TTS，用于路人、群众等未命名角色。

### 3. 脚本生成与语音合成

6. **对话稿（脚本）生成**：对每一章，AI 按小说角色将正文拆解、解析为「谁在说什么」的对话稿。若此步发现新角色，可回到步骤 4～5 做角色与 TTS 的增量补充。
7. **TTS 参数化**：将对话稿转换为 TTS 所需格式（如 JSON/SSML 等）。
8. **分段合成**：按参数调用 TTS，生成各句/各段的语音片段。
9. **音频合并**：使用 ffmpeg 等工具将本章所有语音片段合并为一条完整章节音频。

---

## 流程关系小结

```
入口A: 书名/作者 → AI获取全文 ─┐
                              ├→ 全文就绪 → 分章 → 角色抽取与TTS绑定 ⇄ 按章生成脚本（可回溯补角色）
入口B: 上传文件/粘贴内容 → 解析保存 ─┘    → TTS参数化 → 分段合成 → 合并为章节音频
```

- 步骤 4～5 与步骤 6 之间允许**闭环**：脚本生成阶段若发现新角色，可回溯补充角色库与 TTS 绑定，再继续生成。

## 可实现性分析

| 环节 | 是否可实现 | 依赖与说明 |
|------|------------|------------|
| **入口 A：按书名获取全文** | 可实现，但有约束 | 依赖具体书源（网站/API）。需明确书源、爬虫或检索逻辑；涉及版权与合规，建议仅用于有授权的场景或用户自行承担风险。 |
| **入口 B：用户上传文件/粘贴内容** | 完全可实现 | 后端接收文件（multipart）或 raw 文本，解析 txt/epub（如 epub 用 epub.js 或服务端库）得到纯文本即可。无外部依赖。 |
| **分章节** | 完全可实现 | LLM 或规则（正则/标题模式）均可：输入全文或段落流，输出章节边界或带标题的章节列表。长文可分段让 LLM 标出章节号再合并。 |
| **角色抽取** | 完全可实现 | 典型 LLM 任务：输入全文或摘要+样本，输出结构化角色列表（姓名、性别、身份、性格等）。可多轮或分卷处理长文。 |
| **TTS 角色绑定** | 完全可实现 | 输入为角色列表 + 可用 TTS 音色列表（含性别/风格标签），LLM 或规则做匹配；龙套用固定若干音色即可。 |
| **按章生成对话稿（脚本）** | 完全可实现 | 每章正文 + 当前角色表 → LLM 输出「说话人 + 台词 + 旁白」等结构化脚本；发现新角色时写入角色表并可选触发重新绑定。 |
| **TTS 参数化** | 完全可实现 | 脚本已是「谁+说什么」，转成当前 TTS 引擎所需格式（如每段一条 JSON：speaker_id + text，或 SSML）。纯逻辑与数据转换。 |
| **分段合成 + 合并** | 完全可实现 | 调用现有 TTS API/本地引擎按段合成；用 ffmpeg 或音频库按顺序 concat 成一条。均为成熟能力。 |

**结论**：整体**可以实现**。入口 A 依赖书源与合规策略；其余环节以 LLM + 现有 TTS/ffmpeg 即可闭环。建议优先做入口 B + 分章到合并的全流程，再视需要接入入口 A。

## 如何实现：模块与顺序建议

1. **先统一「全文输入」**  
   实现入口 B：上传 txt/粘贴文本（epub 可后补），落库或内存中的「一书 = 一全文」模型。

2. **分章**  
   单模块：输入全文 → 输出章节列表（标题 + 起止或纯文本块）。可用 LLM 或规则，输出固定 JSON 结构。

3. **角色抽取 + TTS 绑定**  
   两个子步骤可做在一个「角色管理」模块：全文或摘要 → 角色表；角色表 + TTS 音色表 → 绑定表。支持后续「脚本阶段发现新角色」时增量写入角色表并补绑定。

4. **按章脚本生成**  
   单模块：一章正文 + 当前角色/绑定表 → 对话稿（结构化）。新角色写入角色表并可选触发重新绑定或仅加一条默认龙套音色。

5. **TTS 参数化 + 调用 + 合并**  
   脚本 → 按段生成 TTS 参数 → 调 TTS 拿音频片段 → 按顺序 concat（ffmpeg 或音频库）→ 输出章节音频。

6. **编排层（Agent 入口）**  
   对外一个任务：「创建有声书」：选入口 A 或 B → 执行 2→3→4→5，其中 4 可循环多章，4 与 3 之间按需回溯补角色。

7. **入口 A（可选）**  
   在编排层加分支：若用户选「按书名」，则先调用「书源适配器」取全文，再与入口 B 汇合到同一「全文就绪」状态。

## 如何让 AI 开发这个 Agent：建议做法

- **把设计 doc 当「唯一需求源」**  
  把本 md 的「需求目标 + 输入输出 + 工作流程 + 流程关系小结」完整提供给 AI（可附上「可实现性分析」和「模块与顺序建议」），并明确：不依赖现有项目代码，从零实现该 Agent。

- **按模块拆任务，一次让 AI 做一小块**  
  例如顺序：  
  1）入口 B：接收文本/文件并落库；  
  2）分章模块（输入全文，输出章节列表）；  
  3）角色抽取 + TTS 绑定模块；  
  4）单章脚本生成模块；  
  5）TTS 参数化 + 调用 + 合并；  
  6）编排层串起 2→3→4→5，支持「脚本发现新角色」时回溯 3；  
  7）可选：入口 A 与书源适配。  
  每步的 prompt 里写清：输入/输出格式、与前后模块的接口（如「分章模块输出 JSON 与角色模块期望的章节结构一致」）。

- **约定好数据格式再开发**  
  先和 AI 定好：全书/章节/角色/绑定/脚本的 JSON 或 DB 表结构，再实现各模块，减少返工。

- **先跑通一条链再扩展**  
  先实现「粘贴全文 → 分章 → 角色+绑定 → 生成一章脚本 → 合成一章音频」，验证端到端可行后再加：多章循环、新角色回溯、入口 A、epub 等。

- **给 AI 的 prompt 可这样起头**  
  「请根据附上的《一个完全基于 AI 的有声书 Agent 设计思考》文档，从零实现该 Agent。当前子任务是：xxx。输入输出格式为：xxx。不要依赖现有项目代码，只实现本子任务所需接口与逻辑。」
